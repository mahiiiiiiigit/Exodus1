# Final 3 Codex prompts — Exodus

Run these **one at a time**, from the `Exodus1` repository root. After each prompt, inspect the diff and run the stated tests before proceeding. Do not ask Codex to redesign the app wholesale.

## Prompt 1 — Make uploaded plans the source of truth and get one vertical slice working
Audit the current code first. Implement a single end-to-end path from building upload to persisted plan review to graph to simulation. Do not use `mockFloorLayout` for uploaded buildings. Use the selected uploaded document's reviewed geometry as the source of truth. Convert normalized source coordinates into one consistent floor-local coordinate system; create a 3D floor mesh, walls/room boundaries, labels, reviewed door openings, stairs, and explicitly labeled exits from that geometry. Keep the original 2D plan visible as a review/reference panel, but make the building/floor view itself genuinely 3D. Preserve source-coordinate provenance and manual review; do not hallucinate missing walls, doors, rooms, or exits. Add an explicit error/empty state for no reviewed geometry, missing Gemini key/quota, invalid geometry, and zero graph connections. Do not claim successful AI analysis unless the live API request succeeded. First implement and test ONE uploaded floor; keep existing demo routes working. Run all backend tests, frontend tests, TypeScript check, and production build. Report files changed, exact limitations, and test results.

## Prompt 2 — Integrate building/floors, reviewed connections, and synchronized 3D simulation
Continue from the current code without undoing Prompt 1. Make each uploaded floor document map to its actual floor number. Floor selection must load that floor's reviewed geometry/model, not a hard-coded layout. Add multi-floor connectivity only when reviewed evidence confirms that stairs/lifts correspond between floors; never connect by proximity or matching names alone. Use the same geometry/graph state for routes, fire/smoke propagation, and occupant positions in the 3D view. Render reviewed doors/openings and route segments from validated graph edges. Animate occupants only along backend-returned, validated paths; if a room has no path to an explicitly labeled exit, show it as unreachable and do not animate it along a fake route. Fire/smoke should visibly evolve in 3D and update graph danger/blocked edges from the same simulation state. Add tests for floor selection, geometry coordinate conversion, passage connectivity, unreachable rooms, blocked paths, and simulation state synchronization. Do not label the result safety-certified. Run all tests, typecheck, and build; report real versus mocked behavior.

## Prompt 3 — Submission hardening and reliable demo path
Perform a focused integration audit; do not add speculative features or perform a broad UI rewrite. Fix only reproducible issues. Verify startup from a clean checkout using `backend/.env.example`, fresh Python venv, `pip install -r backend/requirements.txt`, `npm ci`, and both servers. Verify `/health`, create building, upload a PDF/PNG, analyze with Gemini when quota is available, edit/save review geometry, generate graph, inspect connected components, obtain a route for a connected room, trigger fire propagation, and run occupants in 3D. Add a deterministic test fixture/demo mode that is clearly labeled as synthetic and can demonstrate the UI without a Gemini quota, but never present fixture detections as live Gemini output or claim the uploaded plan was analyzed. Add a one-command or clearly documented startup flow, friendly actionable errors, and a concise demo script. Ensure `.env`, API keys, local DB, uploads, and build artifacts are not included in the submission archive. Run every test, TypeScript check, production build, and report each step as PASS/FAIL with evidence. Do not claim “zero bugs”; list remaining blockers plainly.
